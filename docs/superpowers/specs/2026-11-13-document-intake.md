# ТЗ: создание проекта из документа («Создать из ТЗ»)

Статус: черновик на согласование. Код не написан.

## 1. Зачем

Сегодня проект через ИИ создаётся из интервью: ИИ задаёт вопросы, человек
отвечает с нуля. У большинства заказов уже есть документ — техническое
задание, бриф, договор с приложением. Пересказывать его в чате долго, и при
пересказе теряются требования.

Новый сценарий: человек загружает документ, ИИ читает его, спрашивает только
о том, чего в документе нет, и предлагает план — этапы и задачи. Каждая задача
ссылается на пункт документа, из которого она появилась.

## 2. Что входит в первую версию

- Загрузка одного документа при создании нового проекта.
- Выбор типа проекта из трёх: «Разработка ПО», «Маркетинговое мероприятие»,
  «Другое». ИИ предлагает тип по тексту, человек подтверждает или меняет.
- Выжимка требований из документа.
- Уточняющие вопросы, набор которых зависит от типа проекта.
- Резюме, черновик плана, применение — как в нынешнем интервью.
- Ссылка на пункт документа в каждой задаче и список требований, не попавших
  ни в одну задачу.
- Документ хранится при проекте, его можно скачать.

## 3. Что не входит (бэклог)

- Смета («Предложение») из документа.
- Редактируемые шаблоны типов проектов на уровне организации.
- Сканы и фотографии документов (распознавание текста).
- Повторная загрузка обновлённого документа в существующий проект.
- Несколько документов на один проект.
- Таблицы и картинки внутри документа: читается только текст.

## 4. Сценарий глазами пользователя

1. На странице проектов рядом с «Создать проект» и «Создать через интервью»
   появляется «Создать из ТЗ».
2. Экран загрузки: поле для файла, под ним строка «Документ будет отправлен в
   модель, подключённую вашей организацией». Форматы и предел размера названы
   на экране.
3. После загрузки ИИ показывает, какой тип проекта он увидел в документе, и
   короткое описание в одну-две фразы. Человек подтверждает тип или выбирает
   другой.
4. Экран «Что мы поняли из документа»: пронумерованный список требований с
   указанием раздела. Список можно править: удалить лишнее, исправить
   формулировку, добавить пропущенное.
5. Уточняющие вопросы — по одному, как сейчас. Задаются только по темам,
   которых нет в документе. Если документ покрывает всё, шаг пропускается.
6. Резюме — как сейчас, редактируемое.
7. Черновик плана — как сейчас, редактируемый. Отличия:
   - у задачи видно, из каких требований она появилась;
   - под черновиком блок «Не вошло в план» со списком требований без задач.
     Пустой блок не показывается.
8. «Применить» создаёт проект. Отмена одной кнопкой работает как сейчас.
9. В настройках проекта появляется блок «Исходный документ»: имя файла, дата,
   кто загрузил, кнопка «Скачать».

Если человек закрыл вкладку на любом шаге, сессия сохраняется и продолжается с
того же места — как нынешнее интервью.

## 5. Типы проектов и темы вопросов

Темы лежат в `config/intake_topics.yml`. Файл получает раздел на каждый тип;
нынешний список становится типом «Другое».

**Разработка ПО** (`software`)

| Ключ | О чём спросить |
|---|---|
| `goal` | Какой результат считается успехом |
| `users` | Кто пользователи и сколько их |
| `platforms` | Веб, мобильные приложения, десктоп; какие браузеры и устройства |
| `scope` | Состав функций |
| `integrations` | С какими системами обмен данными |
| `data` | Перенос существующих данных, объёмы |
| `non_functional` | Нагрузка, безопасность, доступность, языки интерфейса |
| `team` | Кто в команде и в каких ролях |
| `breakdown` | Делить план по этапам (анализ, дизайн, разработка, тесты) или по модулям системы |
| `acceptance` | Как принимается работа, кто принимает |
| `deadline` | Сроки и вехи |
| `constraints` | Бюджет, технологии, согласования |
| `out_of_scope` | Что точно не входит |

**Маркетинговое мероприятие** (`event`)

| Ключ | О чём спросить |
|---|---|
| `goal` | Цель мероприятия и как измерить успех |
| `audience` | Кто приглашён и сколько человек |
| `date_venue` | Дата, площадка, формат (офлайн, онлайн, смешанный) |
| `program` | Программа и спикеры |
| `promotion` | Каналы продвижения |
| `contractors` | Подрядчики: площадка, кейтеринг, техника, полиграфия |
| `budget` | Бюджет и кто согласует расходы |
| `team` | Кто отвечает за что |
| `approvals` | Что и с кем нужно согласовать, к каким датам |
| `after` | Что делается после мероприятия: отчёт, рассылка, материалы |
| `out_of_scope` | Что точно не входит |

**Другое** (`general`) — нынешние семь тем без изменений.

Отсутствие файла тем не ломает приложение — правило сохраняется: ИИ тогда сам
выбирает вопросы.

## 6. Документ

### Форматы и пределы

| Параметр | Значение |
|---|---|
| Форматы | PDF, DOCX, TXT, MD |
| Размер файла | до 4 МБ (`MAX_DOCUMENT_BYTES`, настройка) |
| Объём текста | до 300 000 знаков (`AI_MAX_DOCUMENT_CHARS`, настройка) |

4 МБ — потолок размера запроса на Vercel; предел одинаков для обоих способов
развёртывания, чтобы поведение не различалось.

### Отказы при загрузке

Каждый отказ — машинный код, текст даёт интерфейс на трёх языках.

| Код | Когда |
|---|---|
| `document_too_large` | Файл больше предела |
| `document_type_unsupported` | Формат не из списка; определяется по содержимому, а не по расширению |
| `document_unreadable` | Файл повреждён или защищён паролем |
| `document_no_text` | В файле нет текста (скан) |
| `document_too_long` | Текста больше предела |
| `ai_budget_exhausted` | Документ не помещается в остаток дневного бюджета токенов |

Проверка бюджета делается до обращения к модели: объём документа оценивается
заранее, и человек получает отказ сразу, а не после половины работы.

### Извлечение текста

- PDF — библиотекой `pypdf`. Она уже есть в проекте как тестовая зависимость;
  переносится в рабочие.
- DOCX — стандартными средствами Python (документ — это архив с XML). Новая
  зависимость не нужна. Заголовки сохраняются как заголовки: по ним строятся
  ссылки на разделы.
- TXT, MD — как есть, в кодировке UTF-8.

Файл передаётся телом запроса, а не формой: это обходится без новой
зависимости для разбора форм.

### Хранение

Файл хранится в базе данных, в новой таблице `project_documents`:

| Поле | Содержимое |
|---|---|
| `org_id` | Организация |
| `project_id` | Проект; пусто до применения черновика |
| `filename`, `content_type`, `size_bytes` | Как загружено |
| `sha256` | Контрольная сумма |
| `content` | Сам файл |
| `extracted_text` | Извлечённый текст |
| `uploaded_by`, `created_at` | Кто и когда |

Следствия, которые нужно принять:

- Резервные копии базы растут на размер загруженных файлов.
- При удалении проекта документ удаляется вместе с ним.
- Документ незавершённой сессии, к которой не возвращались 30 дней, удаляется
  при следующей загрузке кем-либо из той же организации. Планировщика в
  продукте нет, поэтому уборка делается попутно.

### Кто что может

| Действие | Владелец | Редактор | Наблюдатель | Клиент | Гость по ссылке |
|---|---|---|---|---|---|
| Загрузить документ и создать проект | да | да¹ | нет | нет | нет |
| Скачать документ проекта | да | да | да | нет | нет |

¹ Кроме редактора, ограниченного отдельными проектами: он не создаёт проекты
никаким способом.

Скачивание — новое право в матрице доступа (`DOCUMENT_READ`). Клиенту документ
закрыт по той же причине, что и смета: в ТЗ бывают внутренние пометки и цены.

## 7. Работа ИИ

Принцип продукта сохраняется: ИИ ничего не записывает в проект без явного
подтверждения человека.

### Шаги

1. **Выжимка.** Документ читается один раз. Результат — список требований:
   номер, текст одной-двумя фразами, раздел документа. Плюс предложенный тип
   проекта и краткое описание. Длинный документ читается частями, списки
   склеиваются.
2. **Покрытие тем.** ИИ отмечает, какие темы выбранного типа документ уже
   закрывает.
3. **Вопросы.** Только по незакрытым темам. Предел числа вопросов прежний
   (`AI_MAX_QUESTIONS`).
4. **Резюме.** Как сейчас.
5. **Черновик.** Как сейчас, но каждая задача несёт номера требований, из
   которых она появилась.

Со второго шага в модель уходит выжимка, а не полный текст документа. Иначе
документ на пятьдесят страниц оплачивался бы заново при каждом вопросе.

### Ссылки на требования

- В описание каждой задачи дописывается строка вида «По ТЗ: п. 3.2, 3.4».
- Список «Не вошло в план» считает сервер, а не модель: это требования, на
  которые не сослалась ни одна задача черновика. Список пересчитывается при
  каждой правке черновика.
- Задача без ссылки допустима: человек или ИИ могут добавить работу, которой в
  документе нет (например, «Развёртывание»).

### Текст документа — данные, а не команды

В документе может оказаться фраза вроде «игнорируй предыдущие указания».
Текст документа передаётся модели как материал для разбора, отдельно от
инструкций. Ответ модели проверяется по схеме на сервере, как сейчас. Даже
если модель ошибётся, результат — только черновик, который человек видит до
применения.

### Лимиты

Действуют нынешние: число обращений в минуту и дневной бюджет токенов на
организацию. Неудачные обращения тоже считаются.

## 8. Изменения в данных

- Новая таблица `project_documents` (см. выше).
- Сессия интервью (`ai_sessions`) получает поля: тип проекта, ссылка на
  документ, выжимка требований.
- Новые статусы сессии перед нынешним `interview`: «документ загружен, тип не
  подтверждён» и «требования на проверке».
- Одна миграция; существующие сессии получают тип «Другое» и продолжают
  работать как раньше.

Обычное интервью без документа остаётся и получает выбор типа проекта: набор
вопросов зависит от типа и там.

## 9. Интерфейс

- Новый экран `/projects/new/document` с шагами из раздела 4. Нынешний экран
  интервью переиспользуется для шагов «вопросы», «резюме», «черновик».
- Кнопка «Создать из ТЗ» на странице проектов.
- Блок «Исходный документ» в настройках проекта.
- Все тексты и коды отказов — на азербайджанском, английском и русском.
- Пока идёт выжимка, экран показывает состояние «Читаем документ…»: на
  большом документе это десятки секунд.

## 10. Критерии приёмки

1. Текстовый PDF и DOCX на 30 страниц превращаются в черновик плана; у каждой
   задачи, появившейся из документа, есть ссылка на пункт.
2. Требование, удалённое из черновика вместе с задачей, появляется в блоке «Не
   вошло в план».
3. Для типа «Разработка ПО» ИИ не спрашивает о сроках, если они названы в
   документе, и спрашивает о способе деления плана.
4. Скан отклоняется с сообщением о том, что в файле нет текста.
5. Файл больше 4 МБ отклоняется до чтения.
6. Клиент и гость по ссылке не могут скачать документ и не видят блок в
   настройках.
7. Редактор, ограниченный отдельными проектами, не может начать сценарий.
8. Отмена применения удаляет созданные задачи; документ остаётся при проекте.
9. Документ, не помещающийся в дневной бюджет токенов, отклоняется до
   обращения к модели.
10. Обычное интервью без документа работает как раньше.
11. Тесты не обращаются к сети: модель подменяется записанными ответами, как в
    нынешних тестах интервью.

## 11. Открытые вопросы

1. **Правка списка требований (шаг 4 сценария)** — нужна ли в первой версии?
   Без неё проще и быстрее, но ошибку выжимки придётся исправлять уже в
   черновике плана.
2. **Удаление документа** — нужна ли владельцу кнопка «Удалить документ» в
   настройках проекта, или документ живёт столько же, сколько проект?
3. **Тип проекта после создания** — сохранять ли его на проекте и показывать
   ли где-нибудь? Сейчас он нужен только для вопросов.
